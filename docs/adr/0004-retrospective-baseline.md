# 베이스라인은 소급 아카이브 분석으로 산출한다

도입 전 1~2주 전향적 기록(v1.3 방식)을 폐기하고, 최근 6~12개월의 Linear 아카이브에서 개발자의 명확화성 코멘트·reopen·스펙 편집을 추출해 두 가지를 산출한다: (a) 재질문 빈도 베이스라인(§10 감소율 지표의 분모), (b) 재질문 유형 분류표(F2e 필수 슬롯 목록의 근거).

## Considered Options

전향적 2주 기록은 기각 — 내부 도구 볼륨에서 표본이 10~20건 수준이라 검정력이 없고, Slack PoC와 병행하면 관측 자체가 행동을 바꿔 오염되며, 2주를 대기해야 한다. 소급 분석은 세 문제를 동시에 해소하고 표본을 한 자릿수 이상 키운다.

## Consequences

한 번의 분석으로 성공 지표의 분모와 완결성 스키마의 근거를 함께 얻는다. 분석에서 "요청자 해소 불가" 유형이 다수로 나오면 §2.1의 전제가 부분적으로 틀린 것이며, 명확화의 무게중심을 요청자 대화(F2b)에서 컨텍스트 검색(F2a)·승격(F2c)으로 옮기는 설계 재조정 분기가 발동한다 — 이 분기는 실패가 아니라 설계 정보다.
