## 4. 사용자 시나리오 / 유저 스토리와 수용 기준

### US-1 — 인테이크 (웹)
스테이크홀더로서, 웹 채팅창에 자유롭게 요청을 입력하고 싶다.
- **수용기준**: 간편 로그인(매직 링크/SSO) 후 입력 가능 / 접수 즉시 확인 + 요청 ID 발급 / 코어 세션 생성 / 대시보드에 "명확화 중" 표시.

### US-2 — 인테이크 (Slack)
스테이크홀더로서, Slack에서 봇 멘션/DM/이모지로 요청을 넣고 싶다.
- **수용기준**: 멘션/DM 시 접수 확인이 스레드에 게시 / 동일 코어 세션 생성 / Linear 계정 불필요.

### US-3 — 명확화 (다국어)
스테이크홀더로서, **내 언어로 된** 비즈니스 질문에 답하며 요구를 구체화하고 싶다.
- **수용기준**: 질문은 요청자의 언어로, 한 번에 3~5개 / 질문 생성 전 기존 이슈·문서·**과거 결정 이력** 검색이 수행되어 이미 답이 있는 것은 묻지 않음 / 유사 기존 요청 발견 시 중복 후보 제시 / 완결성 임계치 도달 시 자동 종료 / 기술 용어 미사용.

### US-4 — 목업 확인 (UI 요청에 한해)
스테이크홀더로서, 내 요청이 어떤 화면으로 구현될지 눈으로 확인하고 싶다.
- **수용기준**: UI 변화를 수반하는 요청에만 목업 단계 실행 / 조작 가능한 호스팅 URL 전달 / "요구사항 확인용 목업 — 구현 결과 아님" 워터마크 상시 / 최대 2~3회 반복 수렴, 미수렴 시 에스컬레이션 / 피드백은 어노테이션·코멘트로 / **승인 시 어노테이션에서 확정된 사항이 요구사항 문서에 흡수됨**.

### US-5 — 개발자 승인 게이트 (비동기)
개발자로서, 내 시간대에 맞춰 최종 스펙을 검토하고 승인/질문/백로그/거절을 결정하고 싶다.
- **수용기준**: 4버튼 제공, 비동기 처리 / **내게 온 이유(라우팅 근거)가 표시됨** / SLA와 남은 시간 표시, 리마인더 / **승인 시에만** Linear 이슈 생성 / 반려·질문 시 사유 태그 1클릭(F11 귀속) / 질문 선택 시 요청자 되물음 루프 / **조건부 상정(미해결 오픈이슈 포함) 건은 시각적으로 구분**.

### US-6 — 진행도 역보고
스테이크홀더로서, 내 요청이 어디까지 왔는지 알고 싶다.
- **수용기준**: Linear 상태 변경 시 알림 / Slack 연동 시 DM, 미연동 시 웹 알림/이메일 / 수신자 시간대 인지 발송 / **병합된 요청도 동일하게 역보고 수신**.

### US-7 — 채널 전환
스테이크홀더로서, Slack에서 시작한 명확화를 웹에서 이어가고 싶다.
- **수용기준**: 세션 컨텍스트 채널 간 보존 / 웹에서 전체 히스토리 열람·이어쓰기 / 재설명 불필요.

### US-8 — 거절/백로그 회신 (침묵 방지)
스테이크홀더로서, 내 요청이 진행되지 않더라도 이유를 알고 싶다.
- **수용기준**: 거절/백로그 시 **통제된 사유 목록**에서 선택된 사유를 담은 정중한 회신 / **이의 경로(팀 리드 재검토 요청) 안내** *(v1.4)* / 백로그 항목은 재부상 트리거(§12)에 따라 다시 검토됨을 안내 / 무응답 종결 없음.

### US-9 — 품질 개선 운영
관리자/운영자로서, 정제가 실제로 잘 되는지 실측 신호로 확인하고, 실패 패턴을 근거로 프롬프트·스키마를 안전하게 개선하고 싶다.
- **수용기준**: 프롬프트 버전별 반려율·재질문율·목업 반복 추이 열람 / 전 세션 판독 큐와 판독 기록 저장 / 실패 사례가 유형별 분류되어 세션 드릴다운 가능 / **재질문 유형과 필수 슬롯의 매핑 현황 열람(미매핑 = 스키마 결손 후보)** *(v1.4)* / 프롬프트·스키마 변경은 골든셋 회귀 통과 없이 배포 불가 / 개선 배포 후 재측정 리포트.

### US-10 — 답할 수 없는 질문 *(v1.4 신설)*
스테이크홀더로서, 내가 답할 수 없는 질문 때문에 요청이 멈추지 않기를 바란다.
- **수용기준**: "모르겠다 / 개발팀이 정할 문제다"를 1클릭으로 표시 가능 / 해당 항목이 담당자 지정 오픈이슈로 승격되어 문서에 실림 / 세션이 미완결 상태로 방치되지 않고 조건부로 게이트에 상정됨 / 승격 사실과 사유가 요청자에게 회신됨.

### US-11 — 중복 요청 병합 *(v1.4 신설)*
스테이크홀더로서, 이미 같은 요청이 있다면 새로 만들지 말고 거기에 붙여 달라.
- **수용기준**: 중복 후보가 요청자 언어로 요약 제시됨(무엇이 같은지 근거 포함) / 수락 시 새 이슈를 만들지 않고 기존 이슈에 연결 / 요청자가 해당 이슈의 구독자로 등록되어 진행 상황 수신 / 내 요청 원문과 맥락이 기존 이슈에 코멘트로 첨부되어 소실되지 않음 / 거부 시 정상 명확화 루프로 복귀.
