## 10. 성공 지표
> 모든 "감소율" 지표는 **Phase 0 소급 베이스라인**을 분모로 한다. 베이스라인 없는 지표는 채택하지 않는다.
> *(v1.4)* 지표를 **선행(채택) / 후행(채택) / 품질**로 계층화한다. v1.3은 후행 지표(우회율)에 채택 판단을 전부 걸고 있었고, 그 지표가 움직였을 때는 이미 늦다.

### 선행 지표 — 채택 *(v1.4 신설, F11에서 승격)*
- **세션 중도 이탈율** — 명확화 중 응답을 멈춘 세션 비율. **우회율보다 몇 주 먼저 움직이는 채택 경보.**
- **재사용률** — 2회 이상 요청한 요청자 비율. **롤아웃 정책 강제 하에서 자발적 채택을 보여주는 사실상 유일한 신호.**
- **요청자 소요 시간** — 접수~완결까지 요청자가 실제로 소비한 시간(응답 작성 시간 합). 개발자 시간을 아끼려고 요청자 시간을 과도하게 쓰면 조직 전체로는 손해이며, 무엇보다 우회의 직접 동기가 된다.

### 후행 지표 — 채택
- **우회율** *(v1.4 — 측정 방식 교체)*: **대상 팀에서 세션 귀속(provenance) 없이 생성된 기능 요청 이슈 수 / 전체 기능 요청 이슈 수.** 버그·기술부채는 이슈 타입/라벨로 필터(F10 설정).
  - v1.3의 "개발자 1클릭 태깅" 정의는 폐기한다. **우회가 일어나는 상황(그냥 받는 게 빠름)과 성실한 태깅이 안 일어나는 상황이 정확히 같아서**, 지표가 낙관 방향으로 편향되고 그 편향은 실패가 심할수록 커진다. provenance 스캔은 개발자 액션 0으로 전수 집계된다.
  - **해석 주의**: 롤아웃 정책 발효 후 우회율은 채택 지표가 아니라 **컴플라이언스 지표**다. 강제 하의 실패 모드는 우회가 아니라 **성의 없는 통과**(한 줄 던지고 최소 답변으로 게이트 통과)이며, 이는 우회율에 잡히지 않는다. 재사용률·완결성 점수 분포·게이트 반려 사유가 이를 감지한다.

### 품질 지표
- **개발자 재질문/반려 감소율** — 소급 베이스라인 대비. 게이트 사유 태그 + 이슈 재질문·reopen 신호.
- **명확화 왕복 횟수** — 세션당 평균(완결성 점수와 함께 해석). 방향이 양의적이므로 상한 목표를 함께 둔다.
- **슬롯 승격률** *(v1.4)* — 요청자가 답할 수 없어 오픈이슈로 올라간 비율. §2.1 전제의 상시 검증치.
- **목업 승인까지 반복 횟수** — UI 요청에 한해, 목표 2~3회 이내.
- **리드타임** — 접수→이슈 생성, 접수→완료 역보고. **게이트 대기 시간을 분리 표시**(병목 진단용).
- **자기개선 루프 지표** — 버전별 품질 추이(반려율은 반드시 짝지표 — 승인 후 reopen율·후행 불일치율 — 와 함께 평가: Goodhart 방지), 골든셋 회귀 점수, 개선 사이클 리드타임, **스키마 결손 분류 건수**. judge-인간 일치율은 L2 도입 후에만.

## 11. 리스크와 완화책
- **채택 실패(최대 리스크)** — 스테이크홀더가 봇을 우회하고 개발자에게 직접 요청. 완화: Slack 우선 전달(서식지), 첫 응답 3초, 롤아웃 정책 공지, **provenance 기반 우회 자동 집계**, **선행 지표(이탈율·재사용률·요청자 소요 시간) 상시 관측**, Phase 1 중단 기준(§9) 발동 시 기능 추가 대신 마찰 감소에 재투자.
- **게이트 병목** *(v1.4 신설)* — 모든 요청이 개발자 1인의 결정을 통과하므로 제품이 **새 병목을 만든다**. 완화: 라우팅 규칙·SLA·미응답 자동 백로그(F5), 게이트 대기 시간을 리드타임에서 분리해 상시 관측, 대기 시간 악화 시 승인자 다중화 또는 저위험 요청 유형의 자동 승인 규칙 검토.
- **완결성 스키마 오정렬** *(v1.4 신설)* — 슬롯을 다 채운 문서가 여전히 재질문을 유발하면 개선 루프가 프롬프트만 만지며 헛돈다. 완화: F2e(슬롯 근거 관리), 재질문 유형↔슬롯 매핑을 분기 점검, 미매핑 유형은 **스키마 결손**으로 별도 분류(F13).
- **번역 무결성** *(v1.4 신설)* — 요구사항 정밀성이 제품의 존재 이유인데 번역 구간만 검증 공백이었다. 완화: 원문 상시 보존, 슬롯 단위·요청자 언어 확인(원칙 7), 판독 큐 표본 대조.
- **요청자 해소 불가 비율이 높을 가능성** *(v1.4 신설)* — §2.1의 전제가 부분적으로 틀릴 수 있다. 완화: Phase 0 소급 분석으로 사전 실측, 슬롯 승격 경로로 런타임 대응, 비율이 높으면 §9 Phase 0 (c) 분기로 설계 재조정.
- **Linear Agents API preview 의존** — 핵심 경로는 `issueCreate`+웹훅만 사용, 네이티브화는 어댑터 뒤 격리. 비용 리스크 없음(에이전트 시트 비과금). 관리 대상은 GA 전 변경 가능성. **추가 관측** *(v1.4)*: 벤더가 고볼륨 자동화 기능의 과금 모델을 GA 시점에 변경할 수 있다고 예고했으므로, 네이티브화 결정 시 비용 가정을 재확인한다.
- **LLM 모호성 판정 한계** — 2층 판정(F2c): 룰 백스톱이 과신 통과를 차단, 임계치는 F12 회귀로 튜닝.
- **컨텍스트 검색 품질** — 그라운딩 검색이 엉뚱한 문서를 참조하면 질문이 오염된다. 완화: 검색 결과를 세션에 기록해 판독 시 검증, 호출 상한, 참조 문서 화이트리스트. **v1.4 추가 위험**: 검색 대상에 과거 거절 이력이 포함되면서, 오래되어 무효가 된 거절을 근거로 새 요청을 잘못 차단할 수 있다. 완화: 결정 이력에 유효기간 개념 부여, 거절 이력은 **차단이 아니라 참고 정보로만** 제시.
- **목업 경계의 정직성** — 목업 생성은 코드 생성이며 경계는 정책 규율임을 문서가 인정(원칙 3). 완화: 코드 비전달·라벨 상시·판독 시 위반 점검.
- **목업-문서 진실 원천 분기** *(v1.4 신설)* — 어노테이션에서 확정된 사항이 목업에만 남으면 문서가 진실 원천이 아니게 된다. 완화: 역주입 단계(F4), 게이트의 흡수 완료 표시, 판독 큐 점검.
- **목업 기대치 오해 / 호스팅 보안** — 워터마크·문구 반복, §6 다층 방어.
- **거절의 조직적 파장** *(v1.4 신설)* — 개발자가 서열이 높은 요청자를 거절하는 상황. 완화: 통제된 사유 목록, 이의 경로 명시(F5/F8), 반복 이의는 팀 리드가 정책으로 흡수.
- **자기개선 과설계** — 저볼륨에서 judge/A-B는 무의미. 완화: L1 전수 인간 리뷰 기본, L2/L3 임계치 조건부. **v1.4 확장**: 동일 렌즈를 비용 가드레일·모델 라우팅에도 적용(§6).
- **LLM-judge 편향(도입 시)** — judge·생성 모델 분리, 인간 판독 라벨로 보정, 일치율 관리.
- **Goodhart** — 반려율 단독 최적화 금지, 짝지표 동반 평가. **우회율도 정책 강제 후에는 컴플라이언스 지표임을 명시**(§10).
- **골든셋 오염·노후화 / 개선 드리프트 / 평가 프라이버시** — 평가·개선용 분리, 분기 갱신, 승인 게이트·카나리·롤백 유지, 익명화(§6).
- **다중 스테이크홀더 상충** — 중복 병합이 동작하는 순간 1이슈 N요청자가 발생한다. 완화(Phase 1 최소 모델): 요청자 목록 보유, 역보고 팬아웃, 중복 후보 매칭으로 상충 세션 표면화, 최종 판단은 게이트의 개발자. 정식 모델은 §12.
- **벤더 기능 확장** *(v1.4 재프레이밍)* — "해자 축소" 프레임을 폐기하고 **build-vs-buy 재결정 트리거**로 관리한다(§2.5). 내부 도구는 대체되기를 기꺼워해야 하며, 어댑터 격리와 얇은 추상화가 그 재결정 비용을 낮춘다. 분기별 재평가 + Phase 3의 정식 게이트.
